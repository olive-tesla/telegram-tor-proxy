# 📌 Что это и для чего?

*Кратко*: Данный скрипт на выходе даёт бесплатный **SOCKS5** прокси, используя соединение через сеть Tor.

Подойдёт для \***ускорения**\* соединения (например для **Telegram** или других приложений\утилит)    

Фокус взят именно на Telegram, но может работать и для других сервисов, которые поддерживают SOCKS5, на ваше усмотрение.  

### 📋  Кратко основное
* Скачивает и настраивает Tor Expert Bundle (не требует системной установки Tor).

* Поддерживает мосты через файл BRIDGES.txt.

* Настраиваемый порт (по умолчанию 9090) – задаётся переменной окружения PORT.

* Кросс-платформенный: работает на Windows и Linux.

* Опциональный Docker-образ для быстрого запуска на VPS.

* Встроенная поддержка Xray (VLESS+TLS) для подключений с мобильных устройств.

    * `docker compose logs xray | grep vless`
    * Установить клиент на моб.устройство (например V2Box на iOS, v2rayNG на Android).

### Настройка конфига в клиенте вручную (на всякий случай, пример с V2Box):

    Address - ip вашего vps, порт 443(по умолчанию),  
    flow - xtls-rprx-vision, Network - tcp, tls-tls, Allow Insecure - true, 
    ID\UUID - хранится в /etc/xray/uuid внутри контейнера, 
    извлечь - docker compose exec xray cat /etc/xray/uuid 
    ИЛИ docker compose run --rm xray cat /etc/xray/uuid
    остальное по умолчанию или пусто

### 🚀 Как запустить


1. Установите клиент на моб.устройство (например V2Box на iOS, v2rayNG на Android).


2. Клонируйте репозиторий и перейдите в папку проекта (на вашем VPS).

   `git clone https://github.com/olive-tesla/telegram-tor-proxy.git`  
   `cd telegram-tor-proxy`  


3. Запустите оба сервиса (Tor-прокси и Xray VLESS):

    `docker compose --profile with-xray up --build`


4. Получение ссылки для телефона
    * Linux

    `docker compose logs xray | grep vless`
    
    * Windows
   
    `docker compose logs xray | Select-String "vless"`

Скопируйте строку, начинающуюся с `vless://`.  
Импортируйте её в приложение на телефоне (**V2Box** для iOS, **v2rayNG** для Android).  
В настройках соединения обязательно включите **Allow Insecure** (из-за самоподписанного сертификата).

Если в ссылке вместо IP-адреса указано `CHANGE_ME`, замените его на реальный IP вашего VPS перед импортом.

⏹️ Остановка Xray

- Только остановить Xray (Tor прокси продолжит работать локально):  
  `docker compose stop xray`

При повторных запусках с профилем `with-xray` UUID и сертификат сохраняются.  
Если нужно сбросить данные Xray (UUID, сертификат), выполните `docker compose down -v`, затем снова запустите с профилем.
</details>

- Если скрипт не может (например из-за ограничений) самостоятельно скачать Tor Expert Bundle - вы можете сделать это вручную, следуйте инструкциям в консоли

## 🚀 Первый запуск:
При первом запуске через `SETUP.bat` (start.py) скрипт:

- Создаёт виртуальное окружение .venv (если запущен не в docker), перезапускается из-под него, устанавливает зависимости.
- Загружает **Tor Expert Bundle** (консольную сборку Tor) с офф. сайта Tor Project, через PowerShell WebClient или wget 
- (Можете скачать вручную). Просто поместите .tar.gz архив с tor expert bundle в корень проекта.
- Распаковывает его в подпапку `tor` в корне проекта.
- Генерирует конфигурационный файл `torrc` (конфиг тора) и `config.json` (локальный конфиг для скрипта)
- Формирует прокси-ссылку для Telegram Desktop `tg://socks?server=127.0.0.1&port=9090` и переходит по ней

    
    Telegram перехватывает вызов `tg://`, распознаёт параметры прокси и выводит  
    окно «Добавить прокси» — остаётся лишь подтвердить добавление.

## ️ ⚙️ ️ А это безопасно?
`Кратко: Да`

1. Касательно Tor-соединения: Содержимое сообщений: **Безопасно**

Telegram всегда шифрует трафик между вашим устройством и своими серверами (протокол `MTProto`). 

    Даже если выходной узел Tor — «злой», он увидит только зашифрованные пакеты данных. 
    Прочитать вашу переписку, увидеть фото или узнать пароль владелец узла не сможет.

Это ключевое, что нужно знать обывателю. Остальные подробности касательно безопасности Tor-соединения рекомендую
изучить самостоятельно если вас это интересует.

2. Касательно скрипта:

- **Открытый исходный код** — весь код проекта доступен для проверки, никаких скрытых телеметрий или обращений к сторонним серверам, только к официальному сайту Tor Project при загрузке Tor Expert Bundle.
- **Локальный прокси** — SOCKS5‑порт открыт исключительно на интерфейсе `127.0.0.1`, поэтому доступ из внешней сети или других приложений невозможен без явного разрешения.
- **Никаких модификаций** — скрипт не изменяет исполняемые файлы ни мессенджера Telegram и не вмешивается в его работу, ни файлы Tor (только редактирует конфиг - для добавления мостов).


### Что именно изменено в конфиге: 
- Изменён порт с классического для Tor 9050 на 9090 (во избежание потенциальных конфликтов, если скрипт одновременно используется с Tor Browser).
- Добавляются указанные в `BRIGDES.txt` мосты и флаг `UseBridges 1` (название говорит само за себя), 
- указывает путь до "Транспорта" для мостов (используется встроенный в Tor Expert Bundle, `lyrebird.exe`) 
- Пути к файлам и вывод логов в консоль для удобства (для первых запусков, понять устанавливает ли Tor соединение)
- Флаги CookieAuthentication 1 и DormantCanceledByStartup 1 (Tor "просыпается" сразу при запуске, а не после запроса)

## ⚙️ Как именно Tor Expert Bundle предоставляет прокси?

Во время работы, скрипт запускает фоновый процесс `tor.exe` (из распакованного архива Tor Expert Bundle, скаченного при первом запуске).

`tor.exe` запускается с флагом `-f`+ путь до `torrc`, это заставляет читать именно этот конфигурационный файл `torrc`  
(отредактированный скриптом), в котором указано, на каком порту и адресе открыть SOCKS5 - прокси (в нашем случае 127.0.0.1:9090).

После старта Tor (`tor.exe`) начинает слушать localhost на указанном порте, ожидая входящих подключений (от 127.0.0.1:9090) от приложений на **том же** компьютере.  

Когда какое-либо приложение (например, Telegram или браузер) хочет отправить данные через 127.0.0.1:9090,  
Tor принимает этот запрос и устанавливает соединение с целевым ресурсом.

Впоследствии весь дальнейший обмен данными между приложением и удалённым сервером проходит через этот туннель: приложение  
отправляет запросы на локальный прокси, Tor принимает их, шифрует и передаёт по своей цепочке. Ответы приходят обратно тем же путём.  
В случае использования с моб.устройств - дополнительно разворачивается Xray VLESS прокси сервер, который служит точкой входа для внешних устройств: принимает зашифрованные соединения от телефона и перенаправляет их в Tor‑прокси, работающий локально

### 📌 Плюсы и минусы этого метода:
Минусы этого метода  
1. Падение скорости (прямое соединение между 2-мя устройствами заменяется на цепочку соединений между (суммарно) 5-6-ю устройствами из разных локаций)
2. Нестабильный доступ к некоторым ресурсам. Где-то принципиально ограничено Tor-соединение, а где-то, будет проблема в конкретной exit-node из собранной у вас цепочки соединения.
3. Проблемы с доступом к самому Tor - в некоторых странах доступ к нему изначально тоже **отсутствует**. В большинстве случаев это исправимо -  
Можно использовать мосты.

**Не стоит ожидать стабильной работы 24\7**)  
(Как минимум, придётся менять мосты время от времени.)

Плюсы:
1. Работает
2. Безопасно при обычном использовании в связке с Telegram
3. Бесплатно
4. У вас в распоряжении не просто один прокси, а каждый раз "одно из"  
(в сети Tor активно около `~2500` выходных узлов (exit nodes), и они не фиксированные. Новые появляются, старые уходят).  
Каждый раз при подключении, мы получаем одну из них - она становится нашей выходной точкой.

### Сам Tor при этом тоже ограничен в некоторых странах. 

Поэтому, подключиться к сети Tor "напрямую", например из рф (за редким исключением) невозможно.  
В качестве решения, можно использовать **мосты**.

### Проблема с DNS
Если используете это Tor-соединение `с другими приложениями`(Не актуально для Telegram).  
Если приложение использует режим SOCKS5 без удалённого разрешения DNS, то запросы на определение IP-адреса домена могут пойти напрямую, в обход Tor — поэтому рекомендуется использовать
`SOCKS5h` или настраивать соединение так, чтобы DNS-запросы тоже шли через прокси. 

### В случае с Telegram эта проблема не возникает
Поскольку мессенджер использует внутренний механизм работы с серверами, не полагаясь на системный DNS.  

Telegram использует собственную систему доменных имён (внутри MTProto), поэтому проблема DNS-утечек для него неактуальна  
Для остальных программ рекомендуется использовать `SOCKS5h` прокси, если поддерживается, либо дополнительно настраивать DNS-резолвинг через Tor.

## 📌 Ручная настройка мостов:

Поддерживаемые типы мостов: `webtunnel`,`snowflake`,`obfs4`,`none`(vanilla),`conjure`(пока не готово)
Важно - Tor даёт приоритет мостам в самом начале списка (первым добавленным).

При каждом запуске, скрипт проверяет `BRIDGES.txt` и берёт мосты из него (если добавлены). Если мостов нет - пытается подключиться напрямую.

(если до **"Bootstrapped 100%"** не доходит - поменяйте мосты (сначала попробуйте другого типа))

Если у вас не работают 3 самых доступных вида мостов - `webtunnel`,`obfs4`,`none`(vanilla) - попробуйте `snowflake`.

    (Можно добавить в автозапуск или настроить как службу)

## ❓ Часто задаваемые вопросы

### 🔹 Где взять мосты?

#### Vanilla (обычные): 
        
`https://bridges.torproject.org/options/en` → выберите «`None`» → «`Get bridges`».

#### obfs4, webtunnel

1. `bridges.torproject.org` - выберите «`obfs4`» или кнопка `Just give me bridges!` (по кнопке выдаёт obfs4)
2. `@GetBridgesBot` бот в Telegram - /start и далее по инструкции
3.  Email - `bridges@torproject.org` отправить письмо с почты **Gmail** или **Riseup** (посмотрите на офф.сайте подробную инструкцию)

### 🔹 Можно ли использовать этот прокси с другими программами?

`Да`. 

После запуска скрипта на вашем компьютере активно Tor-соединение, которое слушает адрес `127.0.0.1:9090`.  
Этот адрес можно использовать как SOCKS5‑прокси. Вы можете вручную прописать его в настройках любого приложения, поддерживающего SOCKS5.

### 🔹 Как проверить, что прокси работает?

**Bootstrapped 100%** в консоли, означает что цепочка Tor построена и соединение установлено.  
**Только с этого момента прокси работает**  



Также можно зайти на `check.torproject.org` через что угодно, использующее прокси, для проверки.

### 🔹 Что делать, если Tor Expert Bundle не скачался автоматически?

Скрипт выведет сообщение об ошибке. В таком случае можно попробовать ещё раз либо Вы можете скачать архив вручную:

   1. Перейдите на страницу загрузки Tor Expert Bundle.
   (https://www.torproject.org/download/tor/)


   2. Скачайте версию для Windows(x86_64) или для Linux (обычно GNU/Linux (x86_64))

      (обычно, это .tar.gz архив)

   3. Поместите архив в папку с проектом и запустите скрипт.

### 🔹 Порт 9090 занят. Как изменить?

1. Вручную:  
Вы можете изменить порт, отредактировав переменную `proxy_port` в файле `config.json`.
Сначала запустите скрипт в первый раз, config.json генерируются при первичной настройке.


2. Через переменную окружения PORT перед запуском (для Docker)

    `PORT=9051 docker compose --profile with-xray up -d --build`
